# 설정 (FRD)

## 메타
- **요구사항 ID**: FRD-SET-001
- **버전**: v3.0.0
- **우선순위**: P0
- **상태**: 구현 완료
- **관련 코드**: `src/screens/settings.js`, `src/alarm-lead-times.js`, `src/alarm-scheduler.js`, `src/data-managers.js`
- **관련 PRD**: [PRD §설정](../prd/product_requirements.md#설정)

## 1. 개요

'설정' 화면은 사용자가 애플리케이션의 다양한 동작 방식과 환경을 개인의 필요에 맞게 조정할 수 있는 기능을 제공합니다. 화면은 탭 2개로 나뉩니다 — '고정 알림'(요일·시각 반복 알림 관리)과 '알림 시간'(보스 출현·고정 알림 시각의 몇 분 전에 미리 알릴지). 향후 테마, 언어 등 다양한 설정 항목들이 추가될 예정입니다. 모든 설정은 로컬 스토리지에 저장되어 영구적으로 유지됩니다.

---

## 2. 사용자 시나리오

- **시나리오 1**: 사용자가 '설정' 메뉴를 클릭하면 → 고정 알림 카드가 표시되고 현재 등록된 고정 알림 목록이 보인다.
- **시나리오 2**: "추가" 버튼을 클릭하면 → 고정 알림 추가 모달이 열리고 시간·이름·요일을 입력할 수 있다.
- **시나리오 3**: 유효한 고정 알림을 저장하면 → 로컬 스토리지에 저장되고 알림 목록 UI가 갱신되며 Web Worker에 동기화된다.
- **시나리오 4**: 토글 스위치로 개별 알림을 비활성화하면 → 해당 알림이 흐리게 표시되고 알람 시스템에서 제외된다.
- **시나리오 5**: "삭제" 버튼 클릭 후 확인하면 → 해당 고정 알림이 삭제되고 Web Worker가 동기화된다.
- **시나리오 6**: '알림 시간' 탭을 누르면 → 현재 알림 시간(처음에는 5분 전·1분 전)과 "정각 (항상 알림)"이 보인다.
- **시나리오 7**: '알림 시간' 탭에서 "추가"를 눌러 10을 저장하면 → 목록이 10분 전·5분 전·1분 전·정각이 되고, 보스와 고정 알림 모두 10분 전에도 울린다.

## 4. 수용 기준 (Acceptance Criteria)

- **AC-001**: Given 저장된 고정 알림이 있는 상태 / When '설정' 화면 진입 / Then 모든 고정 알림이 목록으로 표시된다.
- **AC-002**: Given "추가" 버튼 클릭 / When 모달 열림 / Then 입력 필드가 비어 있고 요일 버튼이 모두 활성화 상태이다.
- **AC-003**: Given 시간 입력 없이 저장 시도 / When "저장" 클릭 / Then 유효성 검사 오류 메시지가 표시된다.
- **AC-004**: Given 요일을 하나도 선택하지 않고 저장 시도 / When "저장" 클릭 / Then 유효성 검사 오류 메시지가 표시된다.
- **AC-005**: Given 유효한 고정 알림 저장 / When 저장 완료 / Then LocalStorageManager.addFixedAlarm()이 호출되고 목록이 갱신된다.
- **AC-006**: Given 알람이 실행 중인 상태에서 고정 알림 수정/삭제 / When 저장 완료 / Then Web Worker에 변경사항이 동기화된다.
- **AC-007**: Given 개별 알림의 토글 스위치 조작 / When 토글 변경 / Then 즉시 로컬 스토리지에 상태가 반영되고 해당 항목이 흐리게/선명하게 표시된다.
- **AC-008**: Given 알림 시간을 바꾼 적 없는 사용자 / When 보스 출현 5분 전·1분 전·정각 / Then 기존과 똑같이 울린다.
- **AC-009**: Given 알림 시간에 7분을 추가 / When 새로고침 / Then 7분 전·5분 전·1분 전·정각이 그대로 보이고, 출현 7분 전에 "7분 전, 보스명"이 울린다.
- **AC-010**: Given 알림 시간 5개 등록 / When "추가" 클릭 / Then 모달이 열리지 않고 최대 개수 안내가 표시된다.
- **AC-011**: Given 0, 61, 2.5, 빈 값, 이미 있는 값 / When 모달에서 "저장" / Then 경고가 표시되고 저장되지 않는다.
- **AC-012**: Given 보스가 7분 남은 상태 / When 10분 전 알림을 추가 / Then 그 보스의 10분 전 알림은 울리지 않는다(이미 지난 시각).

## 8. 동작 명세

### 8.1. 기능 접근
사용자는 좌측 사이드바 메뉴 또는 모바일 환경의 '더보기' 메뉴에서 '설정' 메뉴 항목을 클릭하여 '설정' 화면으로 이동합니다.

### 8.2. 화면 구성
- '설정' 화면은 상단 탭(`#settings-tabs`: 고정 알림 / 알림 시간)과 탭마다 하나의 카드(Card)로 구성됩니다. 각 카드는 특정 설정 그룹을 나타내며, 타이틀과 관련 컨트롤을 포함합니다. 탭은 도움말 화면과 같은 `.modal-tabs` / `.tab-button` / `.custom-list-tab-content` 클래스를 씁니다.
- **고정 알림 카드:** 현재 '설정' 화면의 주요 구성 요소로, 사용자가 자신만의 고정 알림을 생성, 관리할 수 있는 기능을 제공합니다.

### 8.3. 고정 알림 목록 표시
- **표시 위치:** '고정 알림' 카드 내부에 리스트 형태로 표시됩니다.
- **정보 내용:** 사용자가 추가한 모든 고정 알림 항목이 표시됩니다. 각 알림은 설정된 시간, 이름, On/Off 토글 스위치, 요일 버튼, 편집 버튼, 삭제 버튼을 포함합니다.
- **시각적 피드백:** 비활성화된 알림은 시각적으로 흐리게(faded) 표시됩니다.
- **요일 표시:** 각 알림의 두 번째 줄에는 요일 버튼이 원형으로 표시되며, 선택된 요일은 활성화(active) 상태로, 선택되지 않은 요일은 비활성화 상태로 표시됩니다. 이 버튼들은 시각적 표시 전용이며 클릭되지 않습니다.

### 8.4. 고정 알림 추가/편집 모달 (Modal)

'고정 알림' 카드의 '추가' 버튼 클릭 또는 목록 내 알림 항목의 '편집' 버튼 클릭 시 모달 창이 나타나 알림을 추가하거나 수정할 수 있습니다.

- **모달 구성:**
    - **제목:** '고정 알림 추가' 또는 '고정 알림 편집'으로 현재 모드에 따라 변경됩니다.
    - **입력 필드:** '시간' (`HH:MM` 또는 `HHMM`), '이름' (`자유 형식`)을 입력할 수 있습니다.
    - **요일 선택:** '일'~'토' 7개의 원형 토글 버튼을 통해 알림이 반복될 요일을 선택합니다.
    - **하단 버튼:** '취소', '저장' 버튼이 있습니다.
- **입력 형식 및 유효성 검사:**
    - **시간:** `HH:MM` 또는 `HHMM` (4자리) 형식만 지원합니다. 초(second) 단위 입력은 허용되지 않으며, 유효한 시간 값이어야 합니다.
    - **이름:** 비워둘 수 없습니다.
    - **요일:** 최소 하루 이상 선택되어야 합니다.
    - 유효성 검사 실패 시 경고 메시지가 표시되고 로그에 기록됩니다.
- **추가 모드 동작:**
    - 모달 오픈 시 입력 필드는 비워지고, 요일 버튼은 모두 활성화 상태로 초기화됩니다.
    - '저장' 시 `id` (`fixed-${Date.now()}`)가 자동 생성되며, `enabled: true` 상태로 `LocalStorageManager.addFixedAlarm()`을 통해 저장됩니다.
- **편집 모드 동작:**
    - 모달 오픈 시 해당 알람의 시간, 이름, 요일 정보가 자동으로 채워집니다.
    - '저장' 시 `LocalStorageManager.updateFixedAlarm()`을 통해 수정된 내용이 업데이트됩니다.
- **후속 처리:** '저장' 성공 시 모달이 닫히고, 알림 목록 UI가 갱신되며, 로그에 기록되고, 알람이 실행 중이면 `Web Worker`에 변경사항이 동기화됩니다.

### 8.5. 고정 알림 활성화/비활성화 (토글)
- **토글 스위치:** 각 알림 항목 옆의 토글 스위치를 사용하여 개별 알림의 활성화/비활성화 상태를 전환할 수 있습니다.
- **상태 반영:** 토글 스위치 조작 시 즉시 로컬 스토리지에 상태가 반영됩니다.
- **시각적 피드백:** 비활성화된 알림은 즉시 화면에서 흐리게 표시됩니다.

### 8.6. 고정 알림 삭제
- **삭제 버튼:** 각 알림 항목 옆의 '삭제' 버튼을 클릭합니다.
- **확인:** 삭제 전 사용자에게 확인 메시지를 표시합니다.
- **실행:** 사용자가 '확인'을 선택하면 해당 고정 알림이 로컬 스토리지에서 제거되고 목록에서 사라집니다.
- **후속 처리:** 삭제 후 목록 UI 갱신 및 `Web Worker` 동기화가 이루어집니다.

### 8.7. 알림 시간 (탭)

보스 출현 시각과 고정 알림 시각의 몇 분 전에 미리 알릴지 정합니다. 정각 알림은 이 설정과 무관하게 항상 울립니다.

- **목록:** `getAlarmLeadTimes()`의 값을 큰 값부터 "N분 전" 행으로 표시합니다. 숫자만 고정 알림의 시각과 같은 크기(`.alarm-time`)로 두고 "분 전"은 작게(`.alarm-time-unit`) 씁니다. 각 행에 '수정'·'삭제' 버튼이 있고, 버튼 이름(`title`)에 몇 분 알림인지 넣습니다. 맨 아래 "정각 (항상 알림)" 행에는 버튼이 없습니다 — 정각 알림의 발화 기록(`alerted_0min`)이 지난 일정을 정리하는 기준이라 끌 수 없게 했습니다.
- **기본값:** 저장된 값이 없으면 5분·1분입니다. 기본값을 미리 저장해 두지 않으므로, 이 기능이 생기기 전부터 쓰던 사용자도 그대로 5분·1분으로 울립니다.
- **추가/수정 모달 (`#lead-time-modal`):** 숫자 입력 하나와 '취소'·'저장' 버튼입니다. Enter로도 저장합니다.
    - 1~60 사이의 정수만 받습니다. 그 밖의 값은 경고를 띄우고 모달을 닫지 않습니다.
    - 이미 있는 값은 거부합니다(수정 중인 자기 자신은 제외).
    - 수정에서 값을 바꾸지 않고 저장하면 모달만 닫습니다(저장·로그·워커 동기화 없음).
    - 모달을 연 뒤 다른 탭에서 목록이 바뀌어, 수정하던 값이 사라졌거나 최대 개수가 찼으면 저장하지 않고 목록을 다시 그린 뒤 안내합니다.
    - 5개가 차 있으면 '추가' 버튼은 모달을 열지 않고 "최대 5개" 안내를 띄웁니다.
- **삭제:** 고정 알림과 같이 confirm을 받은 뒤 지웁니다(모바일의 아이콘 버튼을 잘못 누르는 경우 대비). 모두 지우면 정각 알림만 남습니다.
- **기본값 버튼:** confirm 후 5분·1분으로 되돌립니다.
- **후속 처리:** 변경할 때마다 로컬 스토리지에 저장하고, 목록을 다시 그리고, 로그에 남기고, 알람이 실행 중이면 `syncScheduleToWorker()`로 워커에 반영합니다. 이미 지난 시각의 알림은 울리지 않습니다(예: 보스가 7분 남았을 때 10분을 추가).
- **적용 범위:** 보스 일정과 고정 알림에 같은 알림 시간을 씁니다. 기기·브라우저별 설정이며 공유 링크에 포함하지 않습니다.
- **대시보드 '임박' 표시와의 관계:** 대시보드·PiP의 5분 기준 강조(`BOSS_THRESHOLDS.IMMINENT`)는 이 설정과 별개이며 바뀌지 않습니다.
