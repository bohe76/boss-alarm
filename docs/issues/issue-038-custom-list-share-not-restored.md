# Issue-038: 커스텀 보스 목록을 공유하면 받는 쪽에서 목록이 나타나지 않음

## 1. 개요 (Overview)

커스텀 보스 목록을 선택한 상태로 공유 링크를 만들어 보내면, 링크를 연 사람의 화면에 그 커스텀 목록과 보스가 나타나지 않는다. 프리셋(오딘 등) 공유는 정상 동작한다.

## 2. 문제점 또는 요구사항 (Problem or Requirement)

### 2.1 원인

- 공유 URL(v4 `#d=`)에는 `gameId`(커스텀 목록은 목록 이름)와 스케줄(보스 이름·시각·메모)만 들어간다. 커스텀 목록 정의(`customBossLists` 설정)와 보스별 젠 주기는 담기지 않는다 (`src/screens/share.js`).
- 받는 쪽 `loadInitialData`는 `DB.getBossesByGameId(payload.gameId)`로 받는 사람의 DB에서 보스를 찾는다. 프리셋은 앱 시작 때 누구에게나 DB에 동기화되지만, 커스텀 목록은 만든 사람의 브라우저에만 있어 0건이 나오고, `"URL의 게임 '...'가 DB에 없어 로드를 건너뜁니다"` 로그만 남긴 채 건너뛴다 (`src/app.js`).
- v3.0.5(da.gd 전환)의 회귀가 아니다. 이 분기는 issue-036(커밋 `67c2645`, v3.0.0)부터 있었고, 당시 설계가 "수신자가 동일한 보스 메타데이터를 갖고 있다"를 전제로 했다.

### 2.2 재현

로컬 서버 + Chromium에서 재현 (2026-10-02). 커스텀 목록 `재현용 커스텀`(보스 2개, 주기 120·180분)을 공유한 링크를 새 브라우저 컨텍스트에서 열면: 선택된 목록은 기본값 `odin-main` 그대로, 커스텀 목록·보스·스케줄 모두 0건, hash는 남아 있음. 같은 조건의 프리셋 공유는 정상 적재.

### 2.3 요구사항 (사용자 결정)

- 받는 쪽에서 커스텀 목록과 보스별 젠 주기까지 복원한다.
- 목록에는 시간을 입력하지 않은 보스까지 포함해 보낸 사람의 목록 전체를 싣는다.
- 받는 사람에게 같은 이름의 커스텀 목록이 이미 있으면: 보스 구성이 같으면 그 목록의 시간을 갱신하고(프리셋 공유와 같은 동작), 구성이 다르면 다른 이름으로 만든다.
- 프리셋 공유, v3 `?v3data=` 링크, 기존 v4 링크의 동작은 그대로 유지한다.

## 3. 제안된 해결 방안 (Proposed Solution)

- **포맷**: v4를 유지하고 커스텀 목록일 때만 선택 필드 `b: [{ n: 보스 이름, i: 젠 주기(분) }]`를 추가한다. v5로 올리지 않는다 — 옛 앱(캐시)이 새 링크를 통째로 못 읽게 되기 때문이다. 옛 앱은 `b`를 무시하고 지금처럼 동작한다.
- **발신** (`src/screens/share.js`): 선택된 목록이 커스텀이면 목록의 보스 이름 순서대로 DB의 주기를 붙여 `b`에 싣는다.
- **수신** (`src/app.js` `loadInitialData`): `b`가 있으면 커스텀 목록과 보스(주기 포함)를 먼저 만들고, 실제로 만들어진(또는 재사용한) 목록 이름으로 기존 적재 경로를 탄다.
- **신규 모듈** `src/share-custom-list.js`: 발신 쪽 목록 정의 추출(`getSharedBossDefinitions`)과 수신 쪽 목록 생성·이름 충돌 처리(`importSharedCustomList`).
- `b`가 없는 옛 커스텀 링크는 주기 정보가 없으므로 지금처럼 건너뛴다.

## 4. 해결 과정 및 최종 결과

- **브랜치**: `main` (로컬 작업, 2026-10-02)
- **구현**
  - `src/share-encoder.js`: `encodeV4Data`가 `bosses`를 받으면 `b`로 싣고, `decodeShareData`가 `b`를 검증(타입, 이름 64자, 주기 0~525600분, 최대 200개)해 `bosses`로 반환. `b`가 없으면 반환 형태와 인코딩 결과가 이전과 동일.
  - `src/share-custom-list.js` (신규): `getSharedBossDefinitions`, `importSharedCustomList`.
  - `src/screens/share.js`: 커스텀 목록이면 보스 정의를 함께 인코딩.
  - `src/app.js` `loadInitialData`: 커스텀 목록 공유면 목록을 먼저 만들고 반환된 이름으로 적재. Draft는 받은 스케줄로 채움.
- **독립 코드 리뷰에서 나온 지적과 반영**
  - (HIGH) 이미 오늘 앱을 연 수신자는 Draft가 비어 스케줄러 입력 화면에 받은 시간·주기가 안 보임 → 커스텀 목록 수신 시 `syncDraftWithMain()`으로 Draft를 채우도록 수정. 수정을 되돌리면 E2E가 실패함을 확인.
  - (MEDIUM) 짧은 주기 + 먼 날짜를 넣은 조작 링크가 48h 확장으로 스케줄 수십만 건을 만들어 앱을 멈출 수 있음 → 예상 확장량 5000건 상한(`limitExpansion`) 추가.
  - (LOW) 빈 `b`를 커스텀 공유로 취급하던 것, 지워진 같은 이름 목록의 잔여 보스 행에서 주기를 물려받던 것, 목록 이름 앞뒤 공백 → 각각 수정.
- **검증**: `npm run lint` 통과, 단위 테스트 220건 통과(신규 29건), E2E 9건 통과(커스텀 목록 공유 3건 신규, 실연동 1건은 제외).
- **남은 것 (이 이슈 범위 밖)**: `commitDraft`는 보스 행을 처음 만들 때만 젠 주기를 기록한다. 이미 저장된 커스텀 보스의 주기를 나중에 바꾸면 DB에 반영되지 않아, 공유 링크에도 이전 주기가 실린다. 별도 이슈로 다룬다.
