# Issue-039: 커스텀 보스의 젠 주기를 수정해도 저장되지 않음

## 1. 개요 (Overview)

커스텀 보스 목록에서 이미 한 번 저장한 보스의 젠 주기를 입력 화면에서 바꾸고 "보스 시간 업데이트"를 눌러도 DB의 주기가 바뀌지 않는다. 시간표의 48시간 확장과 공유 링크(issue-038) 모두 처음 저장한 주기를 계속 쓴다.

## 2. 문제점 또는 요구사항 (Problem or Requirement)

- `BossDataManager.commitDraft`(`src/data-managers.js`)는 Draft의 보스가 DB에 **없을 때만** `DB.upsertBoss`로 주기를 기록한다. 이미 있는 보스는 `if (!boss)` 분기를 타지 않아 주기가 처음 값에 고정된다.
- 입력 화면은 Draft의 주기를 보여 주므로 저장 직후에는 바뀐 것처럼 보이지만, 확장은 DB의 주기로 이뤄진다.
- issue-038 코드 리뷰 중 발견. 리뷰어가 0 → 150분으로 고쳐 다시 저장해도 DB가 0으로 남는 것을 실행으로 확인했다.
- 프리셋 보스의 주기는 프리셋이 정한다(프리셋 인터벌 우선). 프리셋에는 이 수정을 적용하면 안 된다.

## 3. 제안된 해결 방안 (Proposed Solution)

- `commitDraft`에서 이미 있는 보스라도, 게임이 프리셋이 아니고 Draft 항목에 주기 값이 있으며 DB 값과 다르면 `DB.updateBoss`로 주기를 갱신한다.
- 프리셋 여부는 `DB.getGame(gameId)?.type === 'preset'`으로 판별한다(`isPresetNamesMatching`과 같은 기준). 커스텀 목록은 `games` 행이 없다.
- 주기 0은 "주기 없음(확장 안 함)"으로 그대로 저장한다 — 사용자가 주기 입력을 비운 경우다. (코드 리뷰 뒤 잠시 "변경 없음"으로 바꿨다가, 입력 화면을 고친 뒤 이 방침으로 돌아왔다. 4절 참고)
- **범위 밖:** 시간을 입력하지 않은 보스의 주기만 바꾼 경우는 여전히 저장되지 않는다. 입력 화면이 시간이 있는 행만 Draft에 넣기 때문이며(`syncInputToText`), 스케줄이 없는 보스는 확장 대상도 아니다. 시간을 입력해 저장하는 시점에 주기도 함께 저장된다.

## 4. 해결 과정 및 최종 결과

- **브랜치**: `main` (로컬 작업, 2026-10-02). 보호 영역(`BossDataManager.commitDraft`) 수정은 사용자 승인 후 진행.
- **구현**: `src/data-managers.js`의 `commitDraft`에 분기 하나를 추가했다. 보스가 이미 있고, 게임이 프리셋이 아니며, Draft 항목에 숫자 주기가 있고 DB 값과 다르면 `DB.updateBoss(boss.id, { interval })`로 갱신한다. `isInvasion` 등 다른 속성은 건드리지 않는다. Draft 항목에 주기 값이 없으면 기존 주기를 유지한다.
- **검증**
  - 단위 테스트 6건(`test/data-managers.test.js` "젠 주기 수정 반영"): 커스텀 보스 주기 변경이 DB와 48h 확장 간격에 반영, `games` 행이 없는 커스텀 목록, 주기 0으로 비우기, 프리셋 보스 주기 불변, 주기 값 없는 Draft, 다른 속성 유지.
  - E2E 1건(`e2e/custom-share.spec.js`): 화면에서 시간만 넣어 저장 → 주기를 1:30으로 고쳐 다시 저장 → DB 주기 90분, 48h 확장, 공유 링크에 90분이 실리는 것까지 확인.
  - `npm run lint` 통과.

### 리뷰 후 보완 (2026-10-02)

- **지적된 문제**: 입력 화면(`renderBossInputs`)은 주기 칸을 Draft에서만 채운다. DB에 주기가 있지만 Draft 항목이 없는 보스(예: 일정 없이 공유받은 보스)는 주기 칸이 비어 보이고, 그 상태로 시간을 넣어 저장하면 Draft의 주기 0이 DB의 주기를 지웠다.
- **수정**: `commitDraft`의 갱신 조건을 `item.interval > 0`으로 바꿨다. 0(빈칸)은 "변경 없음"이며 저장된 주기를 유지한다.
- **이 수정으로 생긴 제약**: 한 번 저장한 커스텀 보스의 주기를 0(주기 없음)으로 되돌릴 수 없다. 다른 값으로 바꾸는 것은 된다. 커스텀 목록 편집은 DB의 보스 행을 지우지 않으므로(`custom-list-manager.js`) 보스를 목록에서 뺐다 다시 넣어도 주기는 남는다. (이 이슈 이전에는 저장한 주기를 아예 바꿀 수 없었다.)
- **더 나은 해결(미적용, 승인 필요)**: `renderBossInputs`가 Draft 항목이 없는 보스의 주기 칸을 DB 값으로 채우면 빈칸과 0을 구분할 수 있어 위 제약이 사라진다. `renderBossInputs`는 보호 영역이라 사용자 승인 없이 손대지 않았다.
- **검증**
  - 단위 테스트: "주기 0(입력 화면의 빈칸)은 변경 없음으로 보고 저장된 주기를 유지해야 한다"로 교체 (같은 묶음 6건 유지).
  - E2E 1건 추가(`a stored zen interval survives a save while its input is blank`): 주기는 있고 일정은 없는 보스를 공유 링크로 받아, 주기 칸이 빈 채로 시간만 넣어 저장해도 받은 주기(90분)가 남고 그 주기로 확장되는 것을 확인.
  - 변이 검증: 조건을 원래대로(`Number.isFinite`) 되돌리면 위 단위 테스트와 E2E가 모두 실패한다.

### 입력 화면 주기 칸 채우기 (2026-10-02, 사용자 승인)

위 "더 나은 해결"을 사용자 승인을 받아 적용했다. "리뷰 후 보완"의 임시 조건과 그 제약은 이 절로 대체된다.

- **`renderBossInputs`** (`src/ui-renderer.js`, 보호 영역): 주기 칸의 값을 `Draft 항목의 주기 → 없거나 0이면 이 목록에 저장된 주기(DB.findBoss) → 없으면 빈칸` 순으로 정한다. 일정 없이 공유받은 보스처럼 Draft 항목이 없는 보스도 저장된 주기가 보인다. 같은 이름의 보스가 다른 게임에 있어도 참조하지 않는다(`BossDataManager.getBossInterval`은 이름만으로 다른 게임까지 찾으므로 쓰지 않았다).
- **`commitDraft`** (`src/data-managers.js`, 보호 영역): 갱신 조건을 처음 구현(`Number.isFinite(item.interval)`)으로 되돌렸다. 주기 0은 "주기 없음"으로 저장된다.
- **왜 이제 안전한가**: 저장 버튼(`handleApplyBossSettings`)은 항상 화면의 값으로 Draft를 다시 만든 뒤 커밋한다(`commitDraft`의 호출부는 여기 하나다). 화면이 저장된 주기를 보여 주므로 칸이 비어 있다면 사용자가 지운 것이다.
- **결과**: 저장한 주기를 다른 값으로 바꿀 수도, 비워서 없앨 수도 있다. 빈칸 저장으로 주기가 지워지던 문제는 재현되지 않는다.
- **남은 한계 (독립 리뷰 지적, 고치지 않음)**: 주기 칸을 지운 뒤 저장하지 않고 다른 화면에 다녀오거나 커스텀 목록을 편집하면 칸이 저장된 값으로 돌아온다. Draft의 0이 "없음"인지 "지움"인지 구분되지 않기 때문이다. 값이 화면에 보이므로 모르는 사이에 바뀌지는 않는다. 지운 직후 바로 저장하면 정상적으로 지워진다. 구분하려면 `syncInputToText`(보호 영역)가 Draft에 "지움"을 따로 기록해야 한다.
- **독립 리뷰**: 승인(의견 있음). v3.0.5에서 남은 Draft(주기 0), 같은 목록 재수신, 45~525,600분 값의 무편집 저장 왕복을 실제 입력 화면으로 확인했고, 사용자가 지우지 않았는데 주기가 지워지는 경로는 찾지 못했다.
- **검증**
  - 단위 테스트 4건 추가(`test/boss-inputs-interval.test.js`): Draft 항목이 없는 보스에 저장된 주기 표시, Draft 주기가 0이어도 저장된 주기 표시, Draft에 주기가 있으면 그 값 우선, 저장된 주기가 없으면 빈칸(다른 게임의 같은 이름 보스 미참조).
  - `test/data-managers.test.js`: "주기를 0으로 비워 저장하면 주기 없음으로 바뀌고 확장을 멈춰야 한다"로 교체.
  - E2E: 일정 없이 공유받은 보스의 주기 칸에 받은 주기(1:30)가 보이고 시간만 넣어 저장해도 90분이 남는 것, 저장한 주기를 비워 저장하면 0이 되는 것을 확인.
  - 변이 검증: `renderBossInputs`의 저장된 주기 참조를 빼면 단위 테스트 2건과 E2E 1건이 실패한다.
  - `npm run lint` 통과, 단위 테스트 241건 통과, E2E 13건 통과(실연동 1건은 제외).
