# Issue-042: 알림 시간(몇 분 전에 알릴지)을 사용자가 정할 수 있게 한다

## 1. 개요 (Overview)

보스 알림은 출현 5분 전·1분 전·정각에 울리도록 코드에 고정돼 있다(`src/alarm-scheduler.js`). 사용자가 이 "몇 분 전"을 직접 추가·수정할 수 있게 한다. 설정 화면은 탭 2개(고정 알림 / 알림 시간)로 나눈다.

## 2. 문제점 또는 요구사항 (Problem or Requirement)

사용자 지시(2026-11-20)와 확인받은 조건:

- 설정 화면에 기존 '고정 알림'과 별도로 '알림 시간'을 둔다. 탭 구조: 고정 알림 / 알림 시간.
- 기본값은 5분·1분. 사용자가 추가·수정할 수 있다.
- 최대 5개 — 기본값 2개를 포함한 전체 개수.
- 범위는 1~60분(분 단위 정수).
- 고정 알림에도 같은 알림 시간을 적용한다.
- 로컬 스토리지에 저장한다.
- 디자인은 현재 스타일(디자인 시스템) 그대로.

## 3. 제안된 해결 방안 (Proposed Solution)

사용자에게 제안해 승인받은 내용:

- **저장**: `v3_settings`의 `alarmLeadTimes`(예: `[5, 1]`). 기존 `LocalStorageManager.get/set`을 호출만 한다. 저장된 값이 없으면 기본값이므로 기존 사용자는 지금과 똑같이 울린다.
- **규칙**: 중복 거부, 정각 알림은 항상 켬(삭제 불가 — `alerted_0min`이 지난 일정 정리의 기준), 전부 삭제 허용(정각만 남음), 공유 링크에는 넣지 않음, 대시보드 '임박' 표시(5분 기준)는 그대로.
- **발화**: `alarm-scheduler.js`가 설정 값을 읽어 `${N}min` 유형을 만들고 문구는 `N분 전, 이름`으로 통일한다. 발화 기록은 `alerted_${N}min` 이름으로 기존 `DB.updateSchedule`에 쓴다.
- **보호 영역은 수정하지 않는다.** 대안(발화 기록을 `alerted: { 분: 시각 }` 한 칸으로 바꾸기)은 `db.js`·`data-managers.js` 보호 영역 6곳 이상과 저장 데이터 변환이 필요해 채택하지 않았다.
- **알려 둔 한계**: 5분·1분이 아닌 값의 발화 기록은 48시간 재구축 때 사라진다(`data-managers.js`가 3개 칸만 복사). 타이머 워커가 지난 시각을 다시 울리지 않으므로 중복 알림은 생기지 않는다. 발화 기록은 탭 2개를 동시에 열었을 때의 중복 방지에만 쓰이고, 그 경우는 같은 1초 안에 일어나 재구축과 겹치지 않는다.

**예상 영향 범위**: `alarm-scheduler.js`(워커로 보내는 알림 목록과 문구), 설정 화면(`index.html`, `screens/settings.js`, `ui-renderer.js`의 새 렌더 함수, `dom-elements.js`), CSS, 테스트, 문서·도움말. 기존 고정 알림 기능은 탭 안으로 마크업만 옮긴다(ID 불변).

## 4. 해결 과정 및 최종 결과

- **브랜치**: `main` (로컬 작업, 2026-11-20). 보호 영역은 수정하지 않았다(`git diff`로 `db.js`·`data-managers.js`·`app.js`·`share-encoder.js`·`preset-loader.js`·`screens/boss-scheduler.js` 변경 없음 확인).
- **구현**
  - `src/alarm-lead-times.js` (신규): `getAlarmLeadTimes()` / `saveAlarmLeadTimes()`. 저장 값은 읽을 때마다 걸러 낸다(1~60 정수, 중복 제거, 큰 값부터, 최대 5개). 키가 없으면 `[5, 1]`, 빈 배열은 그대로(정각만), 값이 들어 있는데 쓸 수 있는 것이 없으면 손상으로 보고 `[5, 1]`.
  - `src/alarm-scheduler.js`: 고정돼 있던 5분·1분·정각을 `[...getAlarmLeadTimes(), 0]` 반복으로 바꿨다. 유형 문자열(`5min`·`1min`·`0min`)과 순서, 문구는 그대로이고 추가 값은 `${분}min` / `N분 전, 이름`이다.
  - 설정 화면: `index.html`에 탭(`#settings-tabs`)과 알림 시간 카드·모달(`#lead-time-modal`)을 추가하고 고정 알림 카드를 탭 안으로 옮겼다(ID 불변). `src/screens/settings.js`에 탭 전환과 추가·수정·삭제·기본값 처리, `src/ui-renderer.js`에 `renderAlarmLeadTimes()`를 추가했다.
  - CSS: `.card-header-actions`(카드 헤더의 버튼 묶음), `.alarm-time-unit`(숫자 옆의 작은 단위 글자) 두 규칙만 추가했다. 행·버튼·탭·모달은 기존 클래스를 그대로 쓴다.
- **제안과 달라진 점** (사용자 확인 받음)
  - 수정 방식: 행 안의 숫자 칸 → '수정' 버튼과 모달. 숫자 칸 방식은 값을 고친 직후 다른 버튼을 누르면 목록이 다시 정렬되면서 그 클릭이 사라진다. 고정 알림이 쓰는 기존 방식과도 같다.
  - 글자 크기: 숫자만 고정 알림의 시각("12:00")과 같은 크기로 두고 "분 전"은 작게 했다(사용자 지시). 한글은 같은 크기에서도 숫자보다 크게 보인다.
- **리뷰 후 보완** (독립 리뷰: 승인, Critical·High 없음)
  - 타이머 워커 테스트 추가(`test/timer-worker.test.js`). 추가한 알림 시간의 발화 기록은 재구축 때 사라지므로, 다시 울리지 않는 것은 워커의 "직전 tick 이후에 지난 시각만 알림" 조건이 지킨다. 이 조건을 깨는 변형(`UPDATE_SCHEDULE`에서 `lastTick` 초기화)에서 테스트가 실패하는 것을 확인했다.
  - 삭제에 confirm 추가(고정 알림과 같게), 값이 같은 수정은 모달만 닫기, 다른 탭에서 목록이 바뀐 경우 저장하지 않고 안내, 손상된 저장 값은 기본값, 버튼 이름에 몇 분 알림인지 표시, E2E의 실시간 의존 완화(알림을 먼저 켜고 일정 추가와 워커 전송을 한 번에).
- **남은 한계 (고치지 않음)**
  - 추가한 알림 시간이 울린 뒤 → 재구축(새로고침·자정)으로 발화 기록이 사라지고 → 기기 시계가 그 시각보다 앞으로 되돌아가면 다시 울린다. 세 가지가 모두 겹쳐야 한다. 5분·1분·정각은 재구축이 기록을 복사하므로 해당 없다. 막으려면 보호 영역(`_expandAndReconstruct`)이 `alerted_*`를 통째로 복사해야 한다.
  - 고정 알림 객체에는 지운 알림 시간의 `alerted_${분}min` 키가 남는다(최대 60개의 숫자, 동작에 영향 없음).
  - 모달을 Escape로 닫을 수 없다(기존 모달 전체가 같음).
- **검증**
  - 단위 테스트: `test/alarm-scheduler.test.js`(기존 5분·1분·정각 동작을 수정 전 코드에서 먼저 고정한 뒤 추가 값 검증), `test/alarm-lead-times.test.js`, `test/settings.lead-times.test.js`(실제 `index.html` 마크업 사용), `test/timer-worker.test.js`. `npm test` 339건 통과, `npm run lint` 통과.
  - E2E: `e2e/baseline.spec.js`에 알림 시간 시나리오 추가 — 탭 전환, 7분 전 추가, 새로고침 후 유지, 실제 타이머 워커가 "7분 전, 보스명"을 울림. `npm run e2e` 14건 통과(1건은 실연동이라 건너뜀).
  - 화면: 데스크톱(1280px)·모바일(390px)에서 두 탭과 모달을 캡처해 확인. 사용자가 로컬 서버로 직접 확인.
